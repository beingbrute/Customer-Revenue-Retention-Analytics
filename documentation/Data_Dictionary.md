# Data Dictionary

This document defines the main fields used across the Python analysis, Snowflake warehouse, and Tableau dashboards.

## Measurement Conventions

* Monetary values are reported in **British pounds (GBP)**.
* Percentage fields are stored on a `0–100` scale. For example, `23.04` represents `23.04%`.
* Cancellation values are stored as positive absolute values.
* Net-revenue fields use sales values minus cancellation values.
* Snowflake identifiers are shown using their uppercase names.

## 1. Raw Transaction Fields

### `RAW.TRANSACTIONS_CLEAN_RAW`

| Field               | Description                                                                                        |
| ------------------- | -------------------------------------------------------------------------------------------------- |
| `INVOICE_NO`        | Transaction invoice identifier. Cancellation invoice numbers may use a cancellation prefix.        |
| `STOCK_CODE`        | Product or stock identifier.                                                                       |
| `DESCRIPTION`       | Original product description from the source workbook.                                             |
| `QUANTITY`          | Number of units recorded on the transaction line. Negative quantities can represent cancellations. |
| `INVOICE_DATE`      | Date and time when the transaction was recorded.                                                   |
| `UNIT_PRICE`        | Price per product unit in GBP.                                                                     |
| `CUSTOMER_ID`       | Customer identifier. This field may be missing in the source data.                                 |
| `COUNTRY`           | Customer or transaction country.                                                                   |
| `SOURCE_YEAR`       | Source worksheet or reporting-year label retained for auditing.                                    |
| `TRANSACTION_TYPE`  | Business classification such as `Sale` or `Cancellation`.                                          |
| `LINE_CATEGORY`     | Classification separating merchandise from non-merchandise or technical records.                   |
| `LINE_VALUE`        | Transaction-line value calculated using quantity and unit price.                                   |
| `DATA_QUALITY_FLAG` | Data-quality classification assigned during Python cleaning.                                       |
| `ANALYSIS_ELIGIBLE` | Boolean field indicating whether the row is eligible for business analysis.                        |

## 2. Standardized Staging Fields

### `STAGING.VW_TRANSACTIONS_STANDARDIZED`

The staging view retains all raw transaction fields and creates the following analytical fields.

| Field                         | Description                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| `INVOICE_DAY`                 | Calendar date extracted from `INVOICE_DATE`.                                         |
| `INVOICE_MONTH`               | First day of the transaction month.                                                  |
| `INVOICE_YEAR`                | Calendar year extracted from the invoice date.                                       |
| `IS_VALID_MERCHANDISE`        | `TRUE` when the row is analysis-eligible merchandise.                                |
| `IS_MERCHANDISE_SALE`         | `TRUE` when the row is a valid merchandise sale.                                     |
| `IS_MERCHANDISE_CANCELLATION` | `TRUE` when the row is a valid merchandise cancellation.                             |
| `GROSS_SALES_VALUE`           | Sale value for valid merchandise-sale rows; otherwise zero.                          |
| `CANCELLATION_VALUE`          | Absolute cancellation value for valid merchandise-cancellation rows; otherwise zero. |
| `NET_REVENUE_VALUE`           | Signed revenue value for valid sales and cancellations; otherwise zero.              |

## 3. Revenue KPI Fields

## 8. Product-Classification Fields

The classification workflow first assigns categories at the normalized-description level and then maps them back to individual stock codes.

| Field                   | Description                                                                       |
| ----------------------- | --------------------------------------------------------------------------------- |
| `STOCK_CODE`            | Product identifier receiving the final classification.                            |
| `CLASSIFICATION_TEXT`   | Normalized uppercase product description supplied to the classification workflow. |
| `DESCRIPTION_ID`        | Unique identifier assigned to each normalized description.                        |
| `PRODUCT_CATEGORY`      | Final business category assigned to the product.                                  |
| `CONFIDENCE`            | Final classification confidence: `High`, `Medium`, or `Low`.                      |
| `CLASSIFICATION_METHOD` | Method responsible for the final product category.                                |
| `LLM_PRODUCT_CATEGORY`  | Original category returned by the local language model.                           |
| `LLM_CONFIDENCE`        | Confidence originally returned by the local language model.                       |
| `RULE_CATEGORY`         | Category suggested by the primary high-precision keyword rules.                   |
| `QA_RULE_CATEGORY`      | Category suggested by the additional quality-assurance rules.                     |
| `ABC_CLASS`             | Product importance group assigned from cumulative revenue contribution.           |

## 9. Classification Methods

| Method                  | Meaning                                                                          |
| ----------------------- | -------------------------------------------------------------------------------- |
| `LLM only`              | Final category was produced by the local language model without a matching rule. |
| `LLM + rule agreement`  | The language model and primary keyword rule returned the same category.          |
| `Keyword rule override` | A high-confidence primary keyword rule corrected the model category.             |
| `QA rule agreement`     | An additional quality-assurance rule confirmed the model category.               |
| `QA keyword correction` | An additional quality-assurance rule corrected the model category.               |
| `Manual QA correction`  | The category was corrected through documented manual review.                     |
